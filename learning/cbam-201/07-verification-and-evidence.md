# Module 7 — Verification & Verifier-Ready Evidence

## 7.1 Verification vs validation
- **Verification** = third-party assurance of the **reported data/numbers** (after the fact).
- **Validation (ETS-style)** = checking the **monitoring plan/methodology** before use.
**Fact** (`../../research/glossary.md`).

Verification is required **only where actual values are used** — defaults don't need it. **Fact**.
It is performed by an **accredited verifier** (ISO/IEC 17029, ISO 14065, Del. Reg. 2025/2551),
never by an affiliate of the data producer (independence / self-review rule). **Fact**.

## 7.2 ISO 14064-3 concepts (the practitioner's language)
| Concept | Meaning |
|---|---|
| **Reasonable vs limited assurance** | degree of confidence; CBAM expects rigorous assurance |
| **Materiality threshold** | misstatement level that would change a user's decision |
| **Inherent risk / control risk** | risk types the verifier assesses and samples against |
| **Data sampling plan** | which records are tested, at what coverage |
| **Plausibility check** | does the number make sense vs benchmarks/route? |

**Fact** (`../../research/cbam-verifier-accreditation.md`).

## 7.3 What the verifier does
1. Reviews the **monitoring methodology** and system boundary.
2. Reviews **evidence** (source records, invoices, meter logs, lab certs).
3. **Recalculates** a sample of values.
4. Assesses **completeness, traceability, plausibility, risk**.
5. May conduct a **site visit**.
6. Issues the **verification report** (enables actual values). **Fact**.

## 7.4 Verifier-ready dossier — what to prepare
- [ ] Monitoring plan + version history.
- [ ] Source-stream inventory + activity data with sources (tickets, invoices, meter logs).
- [ ] Calculation factors + **ISO 17025** lab certificates.
- [ ] Route declaration + route-qualifying parameters.
- [ ] Precursor SEE evidence (verified supplier data or documented defaults).
- [ ] Meter calibration records; uncertainty/tier assessment.
- [ ] Mass-balance workings; transferred-gas/flaring records.
- [ ] Audit trail: raw → derived → declared. **Fact/Claim**
  (`../../research/cbam-data-catalogue.md` G1–G6).

## 7.5 Design implication (why this matters commercially)
The **quality of your evidence pack determines whether actual values survive verification** —
and therefore whether the customer escapes the default penalty. Producing **verifier-grade**
evidence (not just numbers) is the practitioner's core deliverable. **Logic**.

## 7.6 Common verification findings
- Unexpected boundary omissions; transferred gases missed.
- Uncalibrated meters; non-accredited lab factors.
- Inconsistent actual/default mix; weak traceability.
- Precursor SEE unsupported. **Claim** (`../../research/cbam-data-catalogue.md`).
